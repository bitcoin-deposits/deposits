# bitcoin deposits
## 摘要

理想的點對點電子現金版本應能讓線上付款直接從一方快速發送到另一方，且準備工作最少。lightning 網路提供了部分解決方案，但若需要受信任的第三方代為管理狀態，則其核心優勢便會喪失。我們提出一個使用可驗證帳本和擔保品網絡來解決此問題的方案。營運者向其對等節點廣播帳本更新，建立可稽核的帳戶記錄。錢包向這些對等節點廣播不誠實行為的證據，由他們確保帳本維持誠實的營運者。單方面退出被替換為一項保證：只要網路存在，資金就保持可用。我們由此得到一個委託流動性維護、避免設置費用、能夠離線接收付款、且獨立於基礎層擴展的網路

## 簡介

bitcoin deposits 旨在提供快速且可擴展的金鑰控制資金，以無需信任的方式在鏈下運作。鏈上活動隨帳本數量和準備金輪換頻率而擴展。吞吐量隨網路中帳本數量略高於線性增長，使得每秒數百萬筆交易跨越數兆個錢包成為可能

存在明確的取捨：
- 無單方面退出：當營運者失敗時，資金留在網路中
- 無隱私：驗證需要透明度
- 間歇性可用：存款的可用性取決於營運者。錢包應分散資金以提高可用性

我們預期錢包體驗將類似於快速的基礎層，具有與 lightning 網路相似的支付經濟學

## 帳本

帳本是一條不可變的更新鏈，包含前一次更新的 hash 並由帳本的營運者簽署。不同類型的更新有不同的規則，規定何時以及如何使用。帳本是自描述的，其更新公開可用且不可否認，允許任何人評估合規性

帳本有一個活躍的營運者，但由網狀網路協作維護。任何營運者都可以建立帳本，但若他們消失或變得不誠實，將指派不同的營運者及準備金。目前活躍的營運者由用於簽署最近一次共同簽署更新的公鑰識別

## 存款

存款是一個穩定的帳戶，可以發送和接收資金，由 miniscript 控制。開戶時會建立費用表，以及接收資金是否需要錢包簽署的請求。營運者必須允許同一帳本上存款之間的轉帳以及鏈上退出。他們應允許存款支付 lightning 發票

營運者可自行決定是否代表存款建立鏈上資金要約或 lightning 發票。若建立，這些應由法定人數成員共同簽署，且錢包應驗證此簽名。要約和發票不屬於帳本的一部分，因此驗證簽名並保留其作為證據是錢包的責任

## 費用

存款之間、鏈上及透過 lightning 的轉帳需向帳本營運者支付費用。亦有按指定週期定期對餘額收取的費用。所有費用在開設新存款時協商。費用可在指定區塊數後變更，需提前指定區塊數通知，並在開戶時協商的每次調整百分比限制內。法定人數可拒絕共同簽署會造成無利可圖情況的更新，因為他們最終可能需要為此負責

## 轉帳

轉帳的基本形式是同一帳本上兩個存款之間的兩階段操作：一個存款發出發送資金的請求。若有足夠的可用資金，則在帳本上附加一個帶有花費條件的資金鎖定。若花費條件在逾時前被滿足，資金從發送方轉移到接收方，扣除營運者的費用。若達到逾時，鎖定被釋放，扣除較少的營運者費用。透過 miniscript 花費條件，這足以讓任何存款為同一帳本上的其他存款提供橋接和流動性服務

## lightning

擁有 lightning 通道的營運者可允許存款透過 lightning 網路發送和接收。當存款請求 lightning 發票時，營運者透過其 lightning 節點建立發票，要求法定人數成員共同簽署以證明他們承諾在付款後為存款入帳。錢包應保留此共同簽署的發票作為證據。當存款請求支付 lightning 發票時，營運者使用其 lightning 節點支付，並在獲得 preimage 後從存款中扣款

當付款方和收款方都是同一營運者上的存款時，營運者可在內部結算而不透過 lightning 路由，直接對相應存款進行入帳和扣款。這避免了路由費用和故障模式，同時維持相同的會計保證

## 信使

轉帳請求僅在同一帳本上的存款之間移動資金。要跨帳本移動資金，錢包使用信使——在多個帳本上持有存款並在它們之間傳遞轉帳的服務。信使在中繼器上公告容量和每個帳本的方向性費用。當錢包想從帳本 A 發送到帳本 B 時，它在信使的存款上建立轉帳鎖定，並請求信使從其在目標帳本上的存款建立一個到收款方的鎖定。一旦兩個鎖定都建立，錢包向收款方揭示 preimage，收款方完成從信使的轉帳。一旦揭示，信使使用同一個 preimage 完成從發送方到信使的轉帳

這是標準的 hash 時間鎖定合約模式。我們預期信使的出站逾時嚴格早於入站，確保若錢包從未揭示，兩個鎖定都會過期，雙方都不會損失資金。除了由營運者強制執行的逾時保證外，不需要信任

信使應設定每個帳本的費用：對其服務的每個帳本設定 fee_in 和 fee_out。錢包估算路由成本為來源的 fee_out 加上目的地的 fee_in。信使可根據可用流動性按帳本調整費用，自然地重新平衡其頭寸。錢包透過信使在中繼器上的公告發現信使，並根據費用、容量或覆蓋範圍進行選擇

## 通訊

錢包與營運者之間以及營運者之間的所有通訊使用 nostr 中繼器。帳本更新以持久事件發布，由中繼器保留，建立永久的可稽核記錄。錢包與營運者之間的請求和回應是短暫事件，在中繼器上具有較短的 TTL。營運者以可替換事件公告其條款，允許錢包在無需集中式目錄的情況下發現和比較營運者

此架構意味著錢包不需要持久連線——它們可以無限期離線，並透過從任何擁有事件的中繼器重播事件來趕上進度。營運者可透過其監控的任何中繼器聯繫，中繼器的選擇是部署決策，而非協議限制

## 準備金與擔保品

準備金持有在一個 utxo 中，金額大於或等於帳本義務的總和，可由法定人數的多數花費，並在經過一段較長時間後回退給營運者

擔保品是營運者自有的資本，存入並鎖定在法定人數成員的帳本上。每個成員持有一筆營運者資助並鎖定指定期間的擔保品存款。帳本的總義務限制為任何成員持有的最小擔保品鎖定金額的兩倍，且法定人數的期限限制為最短的鎖定時間。這確保擔保品網絡始終有足夠的支撐來覆蓋託管轉移。同一筆擔保品存款可支持多個帳本以提高資本效率，但錢包應偏好擔保品來源不重疊的營運者

義務在建立新的資金要約或發票時強制執行。營運者不能建立會使帳本總義務超過準備金或超過最小擔保品鎖定金額兩倍（取較低者）的要約或發票

## 法定人數

營運者透過在成員的帳本上存入和鎖定擔保品來請求其他營運者加入其法定人數。請求包括擔保品承諾（金額和鎖定期限）以及成員的條款：帳本上存款必須滿足的最低費用表。每個成員必須營運自己的帳本，並可在營運者被證明不合規時沒收營運者的擔保品。成員在其法定人數成員期間指定費用表的限制——營運者不能以低於最嚴格成員最低限額的費用開設存款，以保護成員在託管轉移後不會繼承無利可圖的義務

一旦法定人數建立，準備金被輪換到新的 multisig utxo 中。成員共同簽署有效更新，並在營運者簽署不合規更新時參與恢復。較大的法定人數增加通訊開銷，但降低營運者風險、提高可用性，並使串謀更加困難和昂貴。錢包應偏好較大的法定人數

## 經濟威懾

該協議以經濟威懾取代單方面退出。法定人數成員有直接的經濟動機對不誠實行為採取行動。在正常運營期間，他們從擔保品上賺取適度的費用，但在可證明的不合規行為發生時，他們可以沒收營運者在其帳本上的全部擔保品存款

當錢包懷疑審查時，可透過認證交付向法定人數成員升級請求。成員以少量費用將請求 hash 嵌入其自己的帳本中，建立因果錨定的證據。若營運者未能處理該請求，成員既有證據也有經濟動機來發起爭議

lightning 發票詐騙遵循相同的威懾模式。營運者知道 preimage 是否已收到，但錢包不知道。然而任何付款方都可能向錢包提供 preimage。一次確認的竊盜就會觸發爭議、準備金扣押和擔保品沒收。竊取單筆付款的回報是有限的，但風險是致命的，使得 lightning 竊盜在經濟上不理性，儘管在沒有第三方合作的情況下形式上無法證明

審查和 lightning 威懾的故障模式都是法定人數的一致串謀。該協議無法防範合作竊取的法定人數，但擔保品網絡確保串謀的成本高於其收益。網路的透明性允許錢包和發現市場在存入資金前識別可疑的法定人數結構

## 時間

絕對時間以基礎層為基準衡量。容差不能超過合理的確認數量，以在區塊鏈重組期間維持穩定性

在需要更高容差的地方，我們依賴因果排序。密碼學帳本是一條 merkle 鏈。每次更新證明它是在之前所有更新之後建立的，但不提供關於鏈外資訊的保證。為了構建分散式排序，我們要求共同簽名包含來自共同簽署者帳本的最新更新 hash。然後該 hash 被納入當前更新的 hash 中，成為該鏈以及帳本營運者為其他所有鏈共同簽署的一部分，建立一個因果關係網。這無法明確證明時間，但能證明某些資訊是以特定順序建立的

## 詐騙證明

我們可以透過揭露以錯誤順序建立的資訊來證明各種類型的詐騙。當資訊未被正常網路操作包含時，可透過建立包含證據 hash 的活動將其偷渡進來。一旦被納入營運者簽署的更新中，證據即被揭示為在排序中的不合規位置建立的：

- 營運者已提議將發送到特定地址的鏈上資金記入存款，但簽署的帳本更新不包含適當的入帳，卻包含一條揭示某個區塊 hash 超過允許入帳前確認數量的鏈

- 營運者已代表存款建立 lightning 發票，簽署的帳本更新未記入存款，儘管 preimage 已在鏈中被揭示

- 共同簽名宣告當前帳本 hash 為其自身鏈中較後 hash 之前的 hash

- 受爭議帳本法定人數的成員處於活躍狀態，但未在指定區塊數內依據詐騙證明採取行動

- 簽署或共同簽署不合規的帳本更新

詐騙證明由證據和將嵌入的 hash 連接到被指控營運者帳本的因果鏈組成。該鏈是一系列共同簽署的更新，每個更新包含來自前一環節帳本的 member_ledger_hash。驗證者沿著鏈行走而無需搜索，確認每個環節是簽署的更新，且證明 hash 與嵌入的資料匹配

## 恢復

一旦帳本變得不可用或不合規，法定人數成員可從最後一次合規更新建立自己的帳本延續。他們必須建立新的法定人數並提供擔保品證明。成員然後必須協調花費先前的準備金輸出到潛在後續鏈的抽籤中。此抽籤的獲勝者在其鏈上附加一個收購更新，其他成員附加一個讓渡。錢包繼續定址同一帳本，僅接受由法定人數共同簽署的回覆。錢包應定期查詢網路並重播帳本更新以識別託管變更，在沒有回覆具有預期共同簽名時亦應如此

當不合規行為看似意外（例如帳本在一定數量的區塊內變得不可用）時，託管變更必須尊重原則：僅將覆蓋帳本義務所需的準備金金額發送到抽籤，找零發送回營運者的公鑰。擔保品的控制權不受影響

當存在不合規證明時，超出必要準備金的金額在法定人數成員之間平均分配，且允許沒收成員帳本上持有的擔保品

## 網路健康

一種直接的攻擊是形成串謀營運者的孤島。在其帳本上建立大量義務後，他們協調退出，竊取超過損失擔保品的資金。網路可以防禦此攻擊，除非在內部價值超過將其連接到非串謀網路的擔保品的區域。更高的擔保品比率和更大、更多元的法定人數降低了這些孤立區形成的可能性，但它們可以故意形成，我們不能期望每個錢包都評估整個網路。相反，發現市場應基於圖形分析（如獎品收集演算法）發布營運者問責性的指標

## 結論

我們提出一個擔保品網絡，需要串謀才能竊取，但串謀使風險中的擔保品增長速度快於可竊取的價值。我們使用此網路來保護由全額準備金支持的密碼學帳本。這些帳本代表離線錢包服務帳戶，以換取預先協商的費用。帳本原語支持 miniscript 花費條件，足以支援基本智能合約。網路近乎線性擴展，使大型網路能為數十億個錢包提供服務，交易量超越傳統支付網路
